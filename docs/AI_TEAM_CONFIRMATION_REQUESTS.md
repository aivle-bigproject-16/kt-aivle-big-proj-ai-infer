# AI팀 확인 요청사항

## 1. RGB 배포 골든 픽스처 원본 제공

**질문**

`golden_fixture_deploy.json`이 참조하는 원본 RGB 이미지 20장을 제공할 수 있나요?

**필요한 내용**

- `fixtures_deploy/` 원본 이미지 20장
- 각 이미지가 `golden_fixture_deploy.json`의 파일명 및 해시와 일치하는지 여부
- 결함 판정 이미지와 정상 판정 이미지의 구분
- 골든 이미지의 정본 저장 위치(Git LFS 또는 S3)

**요청 이유**

현재 RGB 모델 레포에는 골든 결과 JSON만 있고 실제 이미지가 없어 동일한 입력을 사용한 배포 회귀 검증을 재현할 수 없습니다.

## 2. CT ONNX 후처리 변경 승인

**질문**

CT ONNX 배포 후처리를 기존 `NMS + IOU`에서 `NMS + IOS + threshold 0.44`로 변경해도 되나요?

**현재 확인된 내용**

- CT 확인요청 회신에 기록된 기존 배포 설정: `NMS + IOU`
- ONNX 20장 검증 통과 설정: `NMS + IOS + 0.44`
- `IOS 0.44`에서는 20장 모두 판정·검출 개수·클래스·confidence 기준 통과
- `IOU 0.5`에서는 중복 검출로 일부 검출 개수 기준 실패

**확인이 필요한 내용**

- `IOS` 사용 승인 여부
- 최종 match threshold
- 최종 운영 후처리 방식
- 변경 승인 시 모델카드와 골든 생성 설정의 수정 여부

## 3. RGB OWLv2 태그 → 계약 결함코드 매핑 (DECISIONS 등록 요청)

**질문**

RGB 서버가 아래 매핑으로 `defectType`을 채워도 되나요? 등록되면 `A-5`의 하위 세부가 됩니다.

| OWLv2 태그 | `defectType` |
| --- | --- |
| `파손·찢김` | `CRACK` |
| `긁힘·스크래치` | `CRACK` |
| `녹·부식` | `SPOT` |
| `오염·이물질` | `SPOT` |
| `벗겨짐·박리` | `SWELLING` |
| `들뜸` | `SWELLING` |
| `정상:금속캡` | 결함에서 제외 |

**요청 이유**

Core §6.5와 §12.4는 `defectType`의 값 집합을 영문 4종으로 못박습니다. 그런데 배포된 RGB 모델은 OWLv2 제로샷이라 한글 태그 6종을 냅니다. 서버가 그 값을 그대로 내보내면 BE의 `defect_result.defect_type`과 vlm 요청 매핑이 모두 계약 밖 값을 받게 됩니다. v0.2.0에서 이 매핑을 어댑터 경계에 넣었습니다.

**함께 확인이 필요한 내용**

- Core §6.5의 "RGB 모델 = `CRACK`(Damaged)·`SPOT`(Pollution) 2종" 서술이 현행 모델과 다릅니다. OWLv2 제로샷 6종으로의 교체를 Core에 반영해야 합니다.
- 같은 절의 "`SWELLING`을 내보내는 모델은 현재 없다"도 이 매핑이 채택되면 더 이상 참이 아닙니다.
- 이미 OPEN인 `L-21`(defectType 값 집합이 갈린다)과 같은 뿌리이므로, 해당 레코드에 이 조치를 덧붙이는 편이 좋겠습니다.

## 4. 개수 게이트 모델에서의 A-4 적용 방식

**질문**

`A-4`는 PASS일 때 최상위 `confidence`를 `1 − (임계값 미만 최고 결함 점수)`로 정의합니다. RGB 게이트는 점수 임계가 아니라 **박스 개수**(`thr_gate 0.10` 이상인 박스가 8개 이상)로 판정하는데, 이때 `1 − (모든 박스 중 최고 점수)`로 계산해도 되나요?

**요청 이유**

`A-4`는 점수 임계 모델을 전제로 쓰인 것으로 보입니다. v0.2.0은 위 방식으로 구현했고, CT는 `A-4`를 문자 그대로 따릅니다.

## 5. 게이트 통과 · 위치 임계 미달 시의 결함 승격

**질문**

RGB 프레임이 게이트(`thr_gate 0.10`, 8개 이상)는 통과했는데 위치 임계(`thr_loc 0.12`)를 넘긴 박스가 하나도 없을 때, 게이트를 통과한 박스 중 최고점 1개를 결함으로 승격해도 되나요?

**요청 이유**

승격하지 않으면 `label = REJECT`, `defects = []`가 나갑니다. Core §6.4·§8상 REJECT 검사는 결함 수만큼 `defect_result` N행을 가져야 하므로, 결함 0개인 REJECT는 DB에 아무 행도 남기지 못하고 결함 통계에서 사라집니다. `C-7`(FAIL의 행 수 규약)과 인접한 문제입니다.

## 6. AI 추론 엔드포인트 인증 (인프라 파트)

**질문**

`POST /infer/ct` · `POST /infer/rgb`가 현재 무인증입니다. 네트워크 정책만으로 충분한가요, 아니면 서비스 간 토큰이 필요한가요?

**요청 이유**

`AI_BASE_URL`이 클러스터 내부 주소(`http://ai-infer:8000`)라 외부 노출은 없지만, 클러스터 안에서는 누구나 GPU 추론을 태울 수 있습니다. v0.2.0 범위 밖으로 두었습니다.
