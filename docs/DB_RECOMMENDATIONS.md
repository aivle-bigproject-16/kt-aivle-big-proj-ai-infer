# DB 권고사항

## RGB 결함 유형 저장

v0.2.0부터 RGB 결함 어댑터가 모델의 한글 태그를 계약 §6.5의 영문 4종으로
변환해 반환한다. 서버 밖으로 나가는 `defects[].defectType` 값은 다음이
전부다.

```text
SWELLING
SPOT
MICRO_DEFECT
CRACK
```

CT는 `MICRO_DEFECT`만, RGB는 매핑 결과에 따라 `CRACK` · `SPOT` ·
`SWELLING`을 낸다. 매핑표는 `docs/V0_2_0_FIX_PLAN.md` §2 C-1에 있다.

DB와 BE에는 다음을 권고한다.

1. `defect_type` 컬럼의 enum 또는 CHECK 제약을 위 4종으로 유지한다.
2. `SWELLING`은 종전 계약 문서상 "출력하는 모델이 없는" 값이었으나, RGB
   매핑이 채택되면 실제로 저장된다. 제약에서 빠져 있지 않은지 확인한다.
3. 한글 값을 수신하기 위한 마이그레이션은 필요 없다. v0.1 계열 서버가
   한글을 보낸 기간의 데이터가 있다면 별도 정리 대상이다.

이전 버전에서 권고했던 "한글 6종 수용" 조치는 철회한다. 그 권고는 서버가
모델 태그를 변환하지 않던 시점의 것이다.
